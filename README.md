# Retrieval-Aware Cross-Lingual Query Rewriting for Korean Questions

A reproducible research pipeline that rewrites Korean questions into English
retrieval queries and compares four strategies under the **same fixed
retriever and corpus**:

1. `raw` - use the original Korean question as the retrieval query.
2. `translate` - use a pre-provided English target query (translate-then-retrieve).
3. `supervised` - use a supervised seq2seq rewriter trained on `(question, target_query)` pairs.
4. `retrieval_aware` - use a rewriter trained with an additional retrieval-margin objective.

The project is designed so that a reviewer can clone the repo, run the local
smoke commands, and produce a comparison report in a minute or two. All smoke
commands work entirely offline through local JSONL fixtures and a mock model
fallback; HuggingFace model support is wired up behind the same API for
non-smoke configs.

## Quickstart

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_*.py'

PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method raw
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method translate

PYTHONPATH=src python3 scripts/train_supervised.py --config configs/local_smoke.yaml
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method supervised --checkpoint output/checkpoints/supervised

PYTHONPATH=src python3 scripts/train_retrieval_aware.py --config configs/local_smoke.yaml
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method retrieval_aware --checkpoint output/checkpoints/retrieval_aware

PYTHONPATH=src python3 scripts/compare_runs.py --runs-dir output/runs --output-dir output/analysis
```

The last command writes `comparison.csv`, `slice_summary.csv`,
`failure_cases.jsonl`, and `report.md` to `output/analysis/`.

## The four methods

| Method            | Query source                                          | Needs `target_query`? | Uses model? |
|-------------------|-------------------------------------------------------|-----------------------|-------------|
| `raw`             | `example.question_ko` (original Korean)               | no                    | no          |
| `translate`       | `example.target_query` (pre-provided English)         | yes                   | no          |
| `supervised`      | Generated by the supervised rewriter                  | no at inference       | yes         |
| `retrieval_aware` | Generated by the retrieval-aware rewriter             | no at inference       | yes         |

All four methods share the same BM25-style retriever and evaluation metrics,
so the only thing that changes between runs is the query string fed into the
retriever.

## Configuration

Every script accepts `--config <path_to_yaml>`. The required sections are
documented inline in `src/crosslingual_rewrite/config.py`; `configs/local_smoke.yaml`
is the canonical minimal example:

```yaml
experiment:
  name: local-smoke
  task_type: evaluation
  seed: 13

data:
  dataset_path: data/smoke_dataset.jsonl
  corpus_path: data/smoke_corpus.jsonl
  split: train

model:
  base_model: google/mt5-small
  checkpoint_dir: output/checkpoints/supervised
  max_input_length: 256
  max_output_length: 64
  use_mock_model_for_smoke: true

training:
  epochs: 1
  batch_size: 2
  learning_rate: 0.0002
  retrieval_loss_weight: 0.5
  output_dir: output/checkpoints

retriever:
  backend: bm25
  top_k: 5

evaluation:
  top_k: 5
  metrics: [recall_at_k, mrr, ndcg, source_diversity, source_language_ratio, faithfulness]

output:
  runs_dir: output/runs
  analysis_dir: output/analysis
```

Flip `model.use_mock_model_for_smoke` to `false` and the training scripts use
the real HuggingFace seq2seq model (`google/mt5-small` by default). The
training loops are in `src/crosslingual_rewrite/training.py`.

## Smoke dataset

`data/smoke_dataset.jsonl` contains 7 examples covering:

- three pure Korean questions (e.g., mountain, kimchi, hangul unicode)
- two mixed Korean-English questions (e.g., `파이썬 dataclass`, BM25)
- one example where the raw Korean question is almost certainly weaker than
  the English target (question asks about Korean hangul unicode, positive doc
  is an English article about the Hangul Unicode block)
- one extra mixed example (Rust ownership)

`data/smoke_corpus.jsonl` contains 13 documents: English technical articles,
Korean-language distractors, and unrelated topics (cooking, weather, urban
gardening, space exploration). Every `positive_doc_id` / `negative_doc_id`
referenced in the dataset resolves to a document in the corpus.

These fixtures are intentionally small - they exist to smoke-test the pipeline
and to make the contrast between raw Korean and translated English queries
visible in the metrics. **They are not a real benchmark.**

## Output directories

Every run of `scripts/run_method.py` creates one run directory:

```
output/runs/<run_id>/
├── config_<run_id>.yaml         - copy of the resolved config
├── summary_<run_id>.csv         - single-row aggregate summary
├── examples_<run_id>.jsonl      - per-example rows (see schema below)
└── errors_<run_id>.jsonl        - per-example errors (may be empty)
```

`run_id` is deterministic for the same config + method + timestamp:
`<experiment_name>_<method>_<UTC_timestamp>_<config_hash>`.

Per-example JSONL schema (also validated by `tests/test_results.py`):

```json
{
  "run_id": "string",
  "method": "raw|translate|supervised|retrieval_aware",
  "example_id": "string",
  "question_ko": "string",
  "query": "string",
  "target_query": "string|null",
  "query_type": "pure_ko|mixed_ko_en|non_ko|other",
  "positive_doc_id": "string",
  "negative_doc_id": "string",
  "retrieved_docs": [
    {"doc_id": "...", "rank": 1, "score": 0.0, "source_language": "en|ko|null", "is_positive": true, "text": "..."}
  ],
  "metrics": {
    "recall_at_k": 0.0,
    "mrr": 0.0,
    "ndcg": 0.0,
    "source_diversity": 0.0,
    "english_source_ratio": 0.0,
    "korean_source_ratio": 0.0,
    "faithfulness": 0.0
  },
  "error": null
}
```

`scripts/compare_runs.py` then writes the following to
`output/analysis/`:

- `comparison.csv` - one row per run with the aggregate metrics.
- `slice_summary.csv` - metrics averaged per `query_type` per run.
- `failure_cases.jsonl` - per-example failures labeled with categories like
  `positive_not_retrieved`, `low_mrr`, `low_source_diversity`,
  `low_faithfulness`, `empty_query`, and `runtime_error`.
- `report.md` - a human-readable summary that embeds those tables.

## Training commands

Supervised:

```bash
PYTHONPATH=src python3 scripts/train_supervised.py --config configs/local_smoke.yaml
```

Retrieval-aware:

```bash
PYTHONPATH=src python3 scripts/train_retrieval_aware.py --config configs/local_smoke.yaml
```

Both scripts pick between a mock trainer (when `use_mock_model_for_smoke: true`)
and the real HuggingFace trainer (otherwise). The mock trainer:

- iterates over the dataset for the configured number of epochs and batches
- logs one structured JSON event per batch to `output/checkpoints/<objective>/training_log.jsonl`
- saves a `MockRewriteModel` checkpoint at
  `output/checkpoints/<objective>/checkpoint.json` that `scripts/run_method.py`
  can load back.

The real trainer uses standard AdamW teacher forcing for the supervised
objective and adds a BM25-margin hinge term with weight
`training.retrieval_loss_weight` for the retrieval-aware objective.

## Evaluation commands

Run each method independently:

```bash
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method raw
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method translate
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method supervised --checkpoint output/checkpoints/supervised
PYTHONPATH=src python3 scripts/run_method.py --config configs/local_smoke.yaml --method retrieval_aware --checkpoint output/checkpoints/retrieval_aware
```

Optional flags:

- `--top-k N` overrides `retriever.top_k` for this run.
- `--limit N` runs only the first `N` examples.
- `--checkpoint DIR` overrides the default checkpoint directory. Required for
  `supervised` and `retrieval_aware` unless the default checkpoint already
  exists.

```bash
PYTHONPATH=src python3 scripts/compare_runs.py --runs-dir output/runs --output-dir output/analysis
```

## Dataset collection

Use `scripts/collect_dataset.py` to convert Korean QA records from MKQA or
XOR-TyDi-style sources into this project's JSONL schema. The collector uses
the fixed BM25 retriever to propose document candidates, then accepts:

- `d+`: the highest-ranked retrieved document whose title/text contains an
  answer string or alias.
- `d-`: the highest-ranked retrieved document that is not positive and does
  not contain any answer string or alias.

This keeps the retriever as a candidate generator rather than blindly trusting
its top result as a label.

From HuggingFace:

```bash
PYTHONPATH=src python3 scripts/collect_dataset.py \
  --source mkqa \
  --corpus data/my_corpus.jsonl \
  --output data/mkqa_ko_train.jsonl \
  --split train \
  --top-k-positive 100 \
  --top-k-negative 20
```

From a local source JSONL export:

```bash
PYTHONPATH=src python3 scripts/collect_dataset.py \
  --source xor_tydi \
  --input-jsonl data/xor_tydi_ko_with_target_query.jsonl \
  --corpus data/my_corpus.jsonl \
  --output data/xor_tydi_ko_train.jsonl
```

MKQA records already include aligned Korean and English queries, so the
collector can use the Korean query as `question_ko` and the English query as
`target_query`. Common XOR-TyDi exports include Korean `question`, `answers`,
and `lang`, but not always an English query field. For XOR-TyDi, add one of
`target_query`, `question_en`, `query_en`, `english_question`, or
`translated_question` before collection.

The same builder can be called from Jupyter:

```python
from crosslingual_rewrite.dataset_builder import build_dataset_from_hf

stats = build_dataset_from_hf(
    source="mkqa",
    corpus_path="data/my_corpus.jsonl",
    output_path="data/mkqa_ko_train.jsonl",
    split="train",
    top_k_positive=100,
    top_k_negative=20,
    limit=1000,
)
stats.to_dict()
```


The suite covers:

- dataset + corpus JSONL loading and required-field enforcement
- query-type classification
- BM25 scoring, stable tie-breaking, top-k behavior
- raw / translate / supervised / retrieval_aware methods with the mock model

No unit test requires a HuggingFace model download.

## Known limitations

- **Smoke data is not a real benchmark.** The bundled JSONL fixtures are
  intentionally tiny and hand-crafted to make the pipeline runnable. Drop in
  a larger benchmark (e.g., a real Korean QA dataset) before drawing
  conclusions.
- **Mock model mode** is for reproducibility and CI only. When
  `use_mock_model_for_smoke: true`, supervised and retrieval-aware methods
  essentially return the gold `target_query`, which lets the pipeline
  run offline but does not reflect the quality of an actual trained model.
- **Faithfulness** is a lexical Jaccard proxy between the generated query
  and the target query tokens. Replace it with a stronger semantic evaluator
  (for example, embedding cosine similarity or a trained faithfulness model)
  before reporting faithfulness numbers in published results.
- **Fixed BM25-style retriever.** The retriever uses a simple tokenizer
  (English word tokens + Korean character n-grams) and a stdlib BM25
  implementation. It is deliberately fixed so all four methods see the same
  scoring function; a production pipeline should swap it for a stronger
  retriever (dense, hybrid, or a Korean-tuned BM25).
